# Add an artist as an unpublished preview

Worked example: Markus Naarttijärvi, `codex/markus-naarttijarvi-preview`, 28 September 2026. This follows Ishtar's `peggy/ishtar-artist-preview` display-only reader and `fbca687` hold-back flag. Her later `ishtar/preview` branch retained the published version separately. Never merge a review branch without Mark's publication instruction.

1. **Read and establish the branch.** Read `AGENTS.md`, `CLAUDE.md` and the relevant installed Next.js guides. Check `git status`, the branch and remote. Use an isolated artist preview branch. Study the previous artist's manifest and changes before choosing formats or prices.
2. **Record verified copy.** Add an unused ID, name, ASCII slug, location and a short sourced bio to `data/artists.ts`. Use an approved portrait in `public/images/artists/`, with its required credit, or `image: ''` for the existing initials fallback. Keep source URLs, approval questions and the filename-to-title mapping in `scripts/artists/<artist>-review.json`. Do not invent a portrait or biography. Add Norwegian copy when approved.
3. **Keep print masters private.** Leave originals outside Git. Markus's are in `~/Desktop/Markus-Naarttijarvi-photos/Print exports/`. `scripts/prepare-markus-assets.mjs <source-directory> <private-pack>` adapts Ishtar's asset preparation: full-image, sRGB, contain-fit studio PNGs in `public/images/products/`, 2200px artwork AVIFs in `public/images/artworks/`, and a private inventory of dimensions and SHA-256 hashes. It creates no print-production masters. Do not crop, stretch or generatively edit the photographs. Run `python3 scripts/v2/warm_backdrops.py <slugs...>` for the shop's warm studio backdrop and manifest.
4. **Add held-back products.** Append unique IDs and slugs to `public/notion-data/products.json`, preserving the supplied titles and descriptions. Set `published: false`, `review: true`, `inStock: false`, `featured: false`. Copy an existing `priceCategory` and supported sizes; prices and frame supplements come from `config/priceCategories.ts`, `config/generated-prices.ts` and `config/frame.ts`. Markus proposes Ishtar's Premium 50x70cm setup, rotated for landscape photographs. The existing artist agreement share is 60% to the artist and 40% to the gallery after printing and delivery costs, not 60% of gross sales. It is not a per-product field.
5. **Check the data source.** In this revision, the shop reads the committed product JSON. `prebuild` syncs articles from Social Agent, not its Product table. Do not publish or modify that shared catalogue for a branch-only preview. If product sync is introduced later, create unpublished source rows and ensure the build retains review markers before relying on local JSON.
6. **Generate one new room per work.** Use built-in ChatGPT image generation with the actual photograph as the artwork reference. Render the art inside the frame during generation, never paste it into a completed room. Use verified furniture/floor references, natural light and realistic proposed print size. Inspect every result for artwork fidelity, scale and room geometry. Keep original renders in `~/Desktop/ScanArt Image Tests/` and record prompts, sources and model uncertainty. Export `<slug>-room-YYYY-MM-DD.avif` at quality 70 and a WebP quality 88 twin, preserving source metadata. Set `secondaryImage` and add the scene dimensions/alt to `lib/shop-scenes.ts` for the artist hero.
7. **Set and verify focus.** Run `python3 scripts/v2/scene_focus.py <slugs...>`. It includes explicitly marked review products. Inspect its match against the frame and check the crop tests; add a measured override to the script if it matched the wrong object. Commit `lib/scene-focus.json` with the images.
8. **Verify the preview boundary.** `lib/server/catalogue-review.ts` enables review only for `VERCEL_ENV=preview`, or local development with `CATALOGUE_PREVIEW=1`. Display routes use `getShopProducts` and related helpers; checkout, sitemap and feeds retain `getAllProducts`. Drafts retain `published: false` in the UI, show Coming soon and cannot enter the basket. Preview metadata is noindex. Ishtar and retired products without `review: true` stay hidden.
9. **Check, commit and deploy the branch.** Run `npm run lint -- --max-warnings 0`, `npm run typecheck`, `npm test -- --project unit` (the repository CI scope), and `VERCEL_ENV=preview npm run build`. Inspect desktop/mobile artist and product pages. Commit only the intended work, without changing Git identity. Push the named preview branch explicitly. Read `gh api repos/SATRUDE/scanart-next/commits/<sha>/statuses` and resolve the successful Vercel deployment URL. Create a Vercel share URL if authentication is required; record its expiry separately, not its access token in Git. Use `curl -L` with a cookie jar to check the artist and at least two product pages through the share link.
10. **Publish only when Mark instructs it.** First confirm the selection, exact titles/descriptions, biography/portrait, formats, borders, price band, room scenes, print proofs and fulfilment masters. Set only approved products to `published: true`, remove their `review` marker and set `inStock: true` when fulfilment is ready. Reconcile Social Agent if required, add approved collection/editorial selections and Norwegian copy, and update publication-sensitive tests and sitemap dates. Re-run all checks and obtain Mark's approval of the resulting publishing change before merging to main. Do not publish other held-back artists incidentally.
